# googleapi: Google APIs for Free Pascal

Google describes every REST API it offers in a machine-readable *Discovery
document* (<https://developers.google.com/discovery>). These documents change
regularly as Google adds or retires resources, methods and fields.

This means that if FPC commits APIs for certain versions of the google APIs,
they will be obsolete after some time.

Earlier versions of this package contained such APIs which were generated by a tool.
But the tool was incomplete which made hand-tweaking some of the units necessary,
forcing us to commit the tweaked units.

The new version of package is based on OpenAPI code generator and is complete:
the generated code no longer needs tweaking by hand

It therefore no longer contains ready-made units for the Google APIs.
Instead it provides:

* **`discovery2pas`**: a converter that downloads (or reads) a Discovery
  document and generates Object Pascal client units for it.
  Run it whenever you need an API, or a newer version of it.
* **`googleapi.client`**: `TGoogleAPIClient`, which handles OAuth2 for Google
  (client credentials, consent, access and refresh tokens) and signs the
  requests of the generated service proxies.
* **`googleapi.oauthredirect`**: `TOAuthRedirectListener`, a small HTTP
  listener on `http://127.0.0.1:<port>` that receives the authorization code
  when the user grants access in the browser.
* Three demos: Google Drive, Google Calendar and Gmail (`examples/`).

The generated code is based on `fcl-openapi` and `fcl-jsonschema`: the
converter turns the Discovery document into an OpenAPI 3.1 document and lets
the `fcl-openapi` code generator write the Pascal units.

As a side effect: RTTI is no longer used to serialize/deserialize,
making the code faster - albeit somewhat bigger.

## Package contents

| Path | Contents |
|------|----------|
| `src/discovery2pas.pp` | The converter program |
| `src/googlediscovery.*.pas` | Discovery document reader and Discovery to OpenAPI conversion |
| `src/googleapi.compat.generator.pp` | Writer for the optional old-style wrapper unit (`-b`) |
| `src/googleapi.client.pp` | `TGoogleAPIClient`: OAuth2 for Google APIs |
| `src/googleapi.oauthredirect.pp` | `TOAuthRedirectListener`: loopback redirect listener |
| `examples/drive` | List a Drive folder, download, export and upload files |
| `examples/calendar` | List calendars and upcoming events |
| `examples/gmail` | List labels and messages, show a message, save attachments |

`fpmake` builds the units and the `discovery2pas` program; `make install` (or
`fpmake install`) installs `discovery2pas` with the other FPC executables.

The package depends on `fcl-base`, `fcl-json`, `fcl-net`, `openssl`,
`fcl-web`, `regexpr`, `fcl-jsonschema` and `fcl-openapi`.

Google APIs use HTTPS, and HTTPS requests use OpenSSL:
the OpenSSL libraries must be installed on the machine where the programs run.

## Generating units for an API

```sh
discovery2pas -s drive -o drive
```

downloads the Discovery document of the preferred version of the Drive API from
`https://www.googleapis.com/discovery/v1/apis` and writes four units:

| Unit | Contents |
|------|----------|
| `drive.Dto.pas` | A class for each schema (`TFile`, `TFileList`, ...) |
| `drive.Serializer.pas` | Class helpers that convert these classes from and to JSON |
| `drive.Service.Intf.pas` | An interface for each resource (`IFiles`, ...) and the `TServiceResult` types (`TFileServiceResult`, ...) |
| `drive.Service.Impl.pas` | A proxy class for each resource (`TFilesProxy`, ...) that implements the interface with HTTP calls |

The prefix (`drive`) is the `-o` value; it may contain a directory
(`-o src/api/drive`).

Other useful options are:

| Option | Meaning |
|--------|---------|
| `-s NAME` | API name as used by Google: `drive`, `calendar`, `gmail`, `sheets`, `youtube`, ... |
| `-V VER` | API version (default: the preferred version) |
| `-f FILE` | Use a Discovery document saved on disk instead of downloading it |
| `-o FILE` | Base name of the generated units (required) |
| `-L` | Date-time values in local time in Pascal (UTC in JSON). Without it, `TDateTime` values are UTC |
| `-e` | Use Pascal enumerated types for enumerations (default: strings) |
| `-a` | Generate asynchronous service calls |
| `-d` | Generate Delphi-compatible code |
| `-C FILE` | Read code generator settings from FILE, see below |
| `-u FILE` | Read and write the interface GUIDs in FILE, so they stay the same when you regenerate |
| `-k` | Keep the intermediate OpenAPI document (`<output>-openapi.json`) |
| `-b FILE` | Also write FILE, a unit with type names and resource classes in the style of the old googleapi units, on top of the generated code |
| `-q` | Less output |

`discovery2pas -h` lists all options.

To find the name and versions of an API, browse
`https://www.googleapis.com/discovery/v1/apis` or the
[Google APIs Explorer](https://developers.google.com/apis-explorer).

### Code generator settings

`-C FILE` reads an ini file with a `[CodeGen]` section. Besides the unit name
settings of `fcl-openapi`, these settings are useful for Google APIs (all are
off by default):

```ini
[CodeGen]
; Dto classes publish their members as properties with private F fields
UseProperties=1
; Dto classes record which properties were assigned; only those are sent
; to the server (implies UseProperties). Useful for PATCH requests.
TrackChanges=1
; Same as -L
ConvertUTC=1
; Dto classes do not free the objects in their properties and arrays
NoObjectOwnership=1
```

With `TrackChanges`, each Dto class has `FieldChanged`, `MarkChanged`,
`HasChanges`, `ClearChanges` and `MarkAllChanged` methods. Objects returned by
the server start with no changes; call `MarkAllChanged` on an object you want
to send in full.

## Using the generated code

### Google Cloud setup

Before a program can call a Google API on behalf of a user, you need an OAuth
client in a Google Cloud project:

1. In the [Google Cloud Console](https://console.cloud.google.com/), create a
   project (or select one).
2. *APIs & Services > Library*: enable the API (for example **Google Drive API**).
3. *Google Auth Platform > Branding* (OAuth consent screen): configure it with
   user type *External*. While the app is in *Testing* status, add the Google
   accounts that may use it under *Audience > Test users*.
4. *Google Auth Platform > Data access*: add the scopes the program uses (for
   example `https://www.googleapis.com/auth/drive`).
5. *Google Auth Platform > Clients > Create client*: application type
   **Desktop app**. Download the JSON file (`client_secret_....json`). It
   contains the client ID and the client secret; keep it private.

One client can be used for several APIs: enable each API and add its scopes.

### Calling an API

```pascal
uses
  fphttpwebclient, opensslsockets, fpoauth2, fpoauth2ini, googleapi.client,
  drive.Dto, drive.Service.Intf, drive.Service.Impl;

var
  Client: TGoogleAPIClient;
  Store: TFPOAuth2IniStore;
  Files: TFilesProxy;
  Res: TFileListServiceResult;
  F: TFile;

begin
  Client:=TGoogleAPIClient.Create(nil);
  Client.WebClient:=TFPHTTPWebClient.Create(Client);
  // Client data and tokens are kept in an ini file
  Store:=TFPOAuth2IniStore.Create(Client);
  Store.ConfigFileName:='google.ini';
  Store.SessionFileName:='google.ini';
  Client.AuthHandler.Store:=Store;
  Client.LoadCredentials('client_secret_XXXX.json');
  Client.Scopes:='https://www.googleapis.com/auth/drive';
  Client.RedirectUri:='http://127.0.0.1:8085';
  Client.AuthHandler.Config.AccessType:=atOffline;
  Client.AuthHandler.LoadSession('me');
  Client.OnUserConsent:=@DoUserConsent;

  Files:=TFilesProxy.Create(nil);
  Files.BaseURL:='https://www.googleapis.com/drive/v3';
  Client.ConfigureService(Files);
  Res:=Files.List(...);
  if Res.Success then
    try
      for F in Res.Value.files do
        Writeln(F.name);
    finally
      ...
    end
  else
    Writeln('Error ',Res.ErrorCode,': ',Res.ErrorText);
  Client.AuthHandler.SaveSession('me');
end;
```

Some useful odds and ends:

* **BaseURL** must be set on every proxy. It is the `rootUrl` followed by the
  `servicePath` of the Discovery document, for example
  `https://www.googleapis.com/drive/v3`,
  `https://www.googleapis.com/calendar/v3` or `https://gmail.googleapis.com`.
  The OpenAPI document written with `-k` lists it under `servers`.
* **Consent**: when there is no valid access token and no refresh token,
  `TGoogleAPIClient` calls `OnUserConsent` with the Google authorization URL.
  The handler shows it to the user and returns the authorization code.
  Google no longer supports the copy-paste (`urn:ietf:wg:oauth:2.0:oob`) flow;
  use aloopback redirect URI and `TOAuthRedirectListener` to receive the code,
  as the demos do.
  Append `&access_type=offline&prompt=consent` to the URL to get a refresh token,
  so later runs need no browser.
* **Results**: each method returns a `TServiceResult` record. Check `Success`;
  on failure `ErrorCode` and `ErrorText` give the HTTP status. `Value` is a
  new object owned by the caller.
* **Freeing**: a Dto object owns the objects in its object-valued properties
  and arrays, and frees them when it is freed. Freeing the result `Value`
  frees everything in it. Do not put one object in two places, and do not
  free an object that is still in a property or array.
* With `UseProperties`, assigning a new object to a property frees the old
  one, and assigning a new array frees the objects that are not in the new array. 
* With `NoObjectOwnership=1` the Dto classes free nothing; 
  free the objects in arrays and properties yourself.
* **Parameters**: parameters without a default value come first, 
  then those with the default from the Discovery document (Gmail's `userId`,
  for example,  defaults to `me`).
  Optional integer and boolean query parameters are always sent,
  with the API default unless you pass another value.
* **Media**: uploading and downloading file content (`alt=media`, upload endpoints) 
  is not generated. The Drive demo shows how to add it to a generated proxy
  (`examples/drive/drivefiles.pas`).
* **Dates**: date-time values are UTC unless the units were generated with
  `-L`. Date-only values (format `date`) are never converted. Empty dates (0)
  are not sent.
* **Read-only fields**: fields that the Discovery document marks as output
  only are not sent to the server.

## Moving from the old googleapi units

Older FPC versions included pre-generated units (`googlebase`,
`googleservice`, `googleclient` and one `google*.pp` unit per API). These are
no longer part of FPC. Generate the units for the APIs you use with
`discovery2pas`. The `-b FILE` option writes an additional unit with type names
and resource classes in the style of the old units, which may reduce the
changes needed in existing code.

# Google Drive demo

Lists a Google Drive folder, downloads a file (exporting Google Docs,
Sheets and Slides to an Office or PDF format) and uploads a file,
using units generated by `discovery2pas` for the Drive API v3.

## Files

| File | Contents |
|------|----------|
| `drive.Dto.pas`, `drive.Serializer.pas`, `drive.Service.Intf.pas`, `drive.Service.Impl.pas` | Generated Drive API units (see *Regenerating the API units*) |
| `drivefiles.pas` | `TDriveFilesClient`: the generated `TFilesProxy` plus media download, export and resumable upload |
| `drivedemo.lpr`, `drivedemo.lpi` | The demo program and its Lazarus project |
| `build.sh` | Builds the demo with `fpc` |
| `google.ini` | Sample configuration file: client data and tokens |
| `client_secret_sample.json` | Sample of the client JSON file downloaded from Google Cloud Console |

## Google Cloud setup

Follow *Google Cloud setup* in `../../README.md`:

enable the **Google Drive API**, add the scope `https://www.googleapis.com/auth/drive` and
create a *Desktop app* client. A client created for one of the other demos can be reused,
but you will need to re-login if you did not specify all scopes.

## Building

```sh
./build.sh
```

or open `drivedemo.lpi` in Lazarus. `build.sh` compiles the package units from
`../../src`; when the googleapi package is installed, `fpc drivedemo.lpr` is
enough. OpenSSL libraries must be installed.

## Configuration

The demo reads the client ID and secret, and stores the tokens, in
`google.ini` next to the executable (or the file given with `-c`).

Either replace the placeholders in the sample `google.ini` with the values of your
client, or import the JSON file you downloaded from Google Cloud Console
(`client_secret_sample.json` shows its format):

```sh
./drivedemo -j ~/Downloads/client_secret_XXXX.json
```

`google.ini` contains the client secret and after the first run, a refresh token:
keep it private.

## Running

On the first run the program prints a Google URL. Open it in a browser on the
same machine and grant access. Google redirects the browser to
`http://127.0.0.1:8085`, where the program receives the authorization code and
exchanges it for tokens. The tokens are stored in `google.ini`, so later runs
need no browser.

```sh
./drivedemo                                   # list My Drive
./drivedemo -l -f /Documents                  # list a folder by path
./drivedemo -l -f 1AbCdEf...                  # list a folder by ID
./drivedemo -d /Documents/report.pdf          # download to ./report.pdf
./drivedemo -d 1AbCdEf... -t copy.bin         # download by ID to a chosen name
./drivedemo -d "/My notes"                    # Google Doc: exported as .docx
./drivedemo -d "/My notes" -e application/pdf -t notes.pdf
./drivedemo -u ./photo.jpg -f /Pictures       # upload into a folder
```

| Option | Meaning |
|--------|---------|
| `-l`, `--list` | List the folder given by `-f` (default action) |
| `-d`, `--download=FILE` | Download FILE (path or ID). Google Workspace documents are exported |
| `-u`, `--upload=LOCALFILE` | Upload LOCALFILE into the folder given by `-f` |
| `-f`, `--folder=FOLDER` | Folder (path or ID) for `-l` and `-u`; default: My Drive |
| `-t`, `--to=LOCALFILE` | Local file name for `-d`; default: the Drive name |
| `-e`, `--export-mime=MIME` | Export format for Google Workspace documents |
| `-c`, `--config=FILE` | Configuration file; default: `google.ini` next to the executable |
| `-j`, `--credentials=FILE` | Import the client JSON file into the configuration file |
| `-s`, `--session=NAME` | Name of the token set in the configuration file; default: `me` |
| `-p`, `--port=PORT` | Local port for the OAuth2 redirect; default: 8085 |
| `-m`, `--manual` | Paste the redirect address instead of running a local listener |
| `-o`, `--logfile=FILE` | Log HTTP requests and responses to FILE |

If the browser runs on another machine, or port 8085 is in use, use `-p PORT`
or `-m`: with `-m` the program asks you to paste the address the browser was
redirected to. Remove the `[session_me]` section from `google.ini` to force a
new consent.

## Regenerating the API units

The Drive units were generated in this directory with:

```sh
discovery2pas -s drive -o drive
```

Run the same command to update them to the current Drive API.
If you don't have an installed `discovery2pas`, build that first:

```sh
mkdir -p lib
fpc -FUlib -FE. ../../src/discovery2pas.pp
./discovery2pas -s drive -o drive
```

Add `-u drive.uuids` to keep the interface GUIDs the same on later runs.
If Google renamed or removed a method or field the demo uses,
the compiler reports it in `drivedemo.lpr` or `drivefiles.pas`.

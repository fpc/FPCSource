# Gmail demo

Lists your labels (Gmail's folders), lists the messages with a label or
matching a search query, shows a message with its attachments and saves an
attachment, using units generated by `discovery2pas` for the Gmail API v1.
Access is read-only (`gmail.readonly` scope).

## Files

| File | Contents |
|------|----------|
| `gmail.Dto.pas`, `gmail.Serializer.pas`, `gmail.Service.Intf.pas`, `gmail.Service.Impl.pas` | Generated Gmail API units (see *Regenerating the API units*) |
| `codegen.ini` | Code generator settings: Dto classes with properties (`UseProperties=1`) |
| `gmailparts.pas` | Message helpers: headers, RFC 2047 encoded words, text body, attachments, base64url data |
| `gmaildemo.lpr`, `gmaildemo.lpi` | The demo program and its Lazarus project |
| `build.sh` | Builds the demo with `fpc` |
| `google.ini` | Sample configuration file: client data and tokens |
| `client_secret_sample.json` | Sample of the client JSON file downloaded from Google Cloud Console |

## Google Cloud setup

Follow *Google Cloud setup* in `../../README.md`:

enable the **Gmail API**, add
the scope `https://www.googleapis.com/auth/gmail.readonly` and create a
*Desktop app* client. A client created for one of the other demos can be
reused.

## Building

```sh
./build.sh
```

or open `gmaildemo.lpi` in Lazarus. `build.sh` compiles the package units from
`../../src`; when the googleapi package is installed, `fpc gmaildemo.lpr` is
enough. OpenSSL libraries must be installed.

## Configuration

The demo reads the client ID and secret, and stores the tokens, in
`google.ini` next to the executable (or the file given with `-c`). Either
replace the placeholders in the sample `google.ini` with the values of your
client, or import the JSON file you downloaded from Google Cloud Console
(`client_secret_sample.json` shows its format):

```sh
./gmaildemo -j ~/Downloads/client_secret_XXXX.json
```

`google.ini` contains the client secret and, after the first run, a refresh
token: keep it private.

## Running

On the first run the program prints a Google URL. Open it in a browser on the
same machine and grant access. Google redirects the browser to
`http://127.0.0.1:8085`, where the program receives the authorization code and
exchanges it for tokens. The tokens are stored in `google.ini`, so later runs
need no browser.

```sh
./gmaildemo                                          # list labels
./gmaildemo -b INBOX                                 # last 20 messages in the inbox
./gmaildemo -b "My label" -n 50                      # last 50 messages with a user label
./gmaildemo -q "has:attachment from:someone@example.com"
./gmaildemo -r 18c2f0a1b2c3d4e5                      # show a message (ID from a listing)
./gmaildemo -r 18c2f0a1b2c3d4e5 -d 1                 # save its first attachment
./gmaildemo -r 18c2f0a1b2c3d4e5 -d 2 -t copy.pdf     # save the second one as copy.pdf
```

| Option | Meaning |
|--------|---------|
| `-l`, `--labels` | List labels: system folders and user labels (default action) |
| `-b`, `--label=LABEL` | List the messages with label LABEL (name or ID, e.g. `INBOX`) |
| `-q`, `--query=QUERY` | List the messages matching a Gmail search query; can be combined with `-b` |
| `-n`, `--count=N` | Maximum number of messages to list; default: 20 |
| `-r`, `--read=ID` | Show message ID: headers, text and attachments |
| `-d`, `--download=N` | With `-r`: save attachment N (1-based) |
| `-t`, `--to=FILE` | Local file name for `-d`; default: the attachment name |
| `-c`, `--config=FILE` | Configuration file; default: `google.ini` next to the executable |
| `-j`, `--credentials=FILE` | Import the client JSON file into the configuration file |
| `-s`, `--session=NAME` | Name of the token set in the configuration file; default: `me` |
| `-p`, `--port=PORT` | Local port for the OAuth2 redirect; default: 8085 |
| `-m`, `--manual` | Paste the redirect address instead of running a local listener |
| `-o`, `--logfile=FILE` | Log HTTP requests and responses to FILE |

A message listing fetches the headers of each message with a separate request,
so listing 20 messages takes 21 requests.

If the browser runs on another machine, or port 8085 is in use, use `-p PORT`
or `-m`: with `-m` the program asks you to paste the address the browser was
redirected to. Remove the `[session_me]` section from `google.ini` to force a
new consent.

## Regenerating the API units

The Gmail units were generated in this directory with:

```sh
discovery2pas -s gmail -C codegen.ini -o gmail
```

`codegen.ini` makes the Dto classes publish their members as properties.
Run the same command to update the units to the current Gmail API.
If you don't have an installed `discovery2pas`, build that first:

```sh
mkdir -p lib
fpc -FUlib -FE. ../../src/discovery2pas.pp
./discovery2pas -s gmail -C codegen.ini -o gmail
```

Add `-u gmail.uuids` to keep the interface GUIDs the same on later runs.
If Google renamed or removed a method or field the demo uses,
the compiler reports it in `gmaildemo.lpr` or `gmailparts.pas`.

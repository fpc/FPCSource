# Google Calendar demo

Lists your calendars and the upcoming events of a calendar, using units
generated by `discovery2pas` for the Calendar API v3.

Event times are shown in local time: the units were generated with `-L`.

## Files

| File | Contents |
|------|----------|
| `calendar.Dto.pas`, `calendar.Serializer.pas`, `calendar.Service.Intf.pas`, `calendar.Service.Impl.pas` | Generated Calendar API units (see *Regenerating the API units*) |
| `calendardemo.lpr`, `calendardemo.lpi` | The demo program and its Lazarus project |
| `build.sh` | Builds the demo with `fpc` |
| `google.ini` | Sample configuration file: client data and tokens |
| `client_secret_sample.json` | Sample of the client JSON file downloaded from Google Cloud Console |

## Google Cloud setup

Follow *Google Cloud setup* in `../../README.md`:

enable the **Google Calendar API**, add the scope
`https://www.googleapis.com/auth/calendar` and create a *Desktop app* client.
A client created for one of the other demos can be reused,
but you will need to re-login if you did not specify all scopes.

## Building

```sh
./build.sh
```

or open `calendardemo.lpi` in Lazarus. `build.sh` compiles the package units
from `../../src`; when the googleapi package is installed,
`fpc calendardemo.lpr` is enough. OpenSSL libraries must be installed.

## Configuration

The demo reads the client ID and secret, and stores the tokens, in
`google.ini` next to the executable (or the file given with `-c`).

Either replace the placeholders in the sample `google.ini` with the values of your client,
or import the JSON file you downloaded from Google Cloud Console
(`client_secret_sample.json` shows its format):

```sh
./calendardemo -j ~/Downloads/client_secret_XXXX.json
```

`google.ini` contains the client secret and after the first run, a refresh token:
keep it private.

## Running

On the first run the program prints a Google URL. Open it in a browser on the
same machine and grant access. Google redirects the browser to
`http://127.0.0.1:8085`, where the program receives the authorization code and
exchanges it for tokens. The tokens are stored in `google.ini`, so later runs
need no browser.

```sh
./calendardemo                               # list calendars
./calendardemo -e primary                    # next 25 events of your own calendar
./calendardemo -e someone@example.com -n 10  # next 10 events of another calendar
```

| Option | Meaning |
|--------|---------|
| `-l`, `--list` | List calendars (default action) |
| `-e`, `--entry=calID` | List the upcoming events of calendar calID (`primary` for your own) |
| `-n`, `--count=N` | Maximum number of events to list; default: 25 |
| `-c`, `--config=FILE` | Configuration file; default: `google.ini` next to the executable |
| `-j`, `--credentials=FILE` | Import the client JSON file into the configuration file |
| `-s`, `--session=NAME` | Name of the token set in the configuration file; default: `me` |
| `-p`, `--port=PORT` | Local port for the OAuth2 redirect; default: 8085 |
| `-m`, `--manual` | Paste the redirect address instead of running a local listener |
| `-o`, `--logfile=FILE` | Log HTTP requests and responses to FILE |

If the browser runs on another machine, or port 8085 is in use, use `-p PORT`
or `-m`: with `-m` the program asks you to paste the address the browser was
redirected to. Remove the `[session_me]` section from `google.ini` to force a
new consent.

## Regenerating the API units

The Calendar units were generated in this directory with:

```sh
discovery2pas -s calendar -L -o calendar
```

`-L` converts date-time values between UTC (in JSON) and local time (in Pascal code).
Without it, the `TDateTime` values are UTC.

Run the same command to update the units to the current Calendar API.
If you don't have an installed `discovery2pas`, build that first:

```sh
mkdir -p lib
fpc -FUlib -FE. ../../src/discovery2pas.pp
./discovery2pas -s calendar -L -o calendar
```

Add `-u calendar.uuids` to keep the interface GUIDs the same on later runs.
If Google renamed or removed a method or field the demo uses,
the compiler will report it in `calendardemo.lpr`.
